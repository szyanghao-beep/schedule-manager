# 日程管理 2.3.0 功能规划（方案二 · 标准均衡）

> 状态：已确认方向，待评审开工。2.2.0 已封版。
> 规划日期：2026-08-23。

## 决策记录（已与用户确认）

1. 记账分类**独立**于日程分类（复用颜色 / 选择器 UI，但两套数据树）
2. 记账采用**账户维度单式**（不上全复式，够 80% 需求）
3. **农历生日**要做（lunar 库每年换算公历日期）
4. 节假日：**内置 2026 + 手动导入新年度**入口
5. **桌面先行**，RN 移动端二期

## 一、目标与范围

2.3.0 交付两大模块：

- **A. 日历增强**：农历、二十四节气、法定节假日 + 调休、生日 / 纪念日提醒
- **B. 收支记账**：多账户 + 流水 + 二级分类 + 预算 + 报表

## 二、功能清单

### A. 日历增强

## 三、数据模型（data.json，schema v4）

**金额统一用整数「分」存储**（避免浮点误差），显示层转「元」。

```jsonc
// 新增顶层数组（v3 → v4 迁移补齐为空数组）
"accounts": [{
  id, name, type: "cash|bank|credit|ewallet|investment|other",
  initialBalance: 0, currency: "CNY", color, icon,
  sortOrder, isArchived: false,
  createdAt, updatedAt, localModifiedAt, deleted
}],

"bookkeepingCategories": [{
  id, name, type: "income|expense", parentId: null,
  icon, color, sortOrder, isDefault,
  createdAt, updatedAt, localModifiedAt, deleted
}],

"transactions": [{
  id, type: "expense|income|transfer", amount: 0,      // 分，正数
  accountId, toAccountId: null, categoryId: null,
  date, note: "",
  createdAt, updatedAt, localModifiedAt, deleted
}],

"budgets": [{
  id, categoryId: null, period: "monthly", amount: 0,   // 分
  createdAt, updatedAt, deleted
}],

"memorials": [{
  id, name, kind: "birthday|anniversary|other",
  calendar: "solar|lunar", month, day, year: null,      // year 用于算年龄 / 起始
  remindBeforeDays: 7, note, categoryId,
  createdAt, updatedAt, localModifiedAt, deleted
}],

// settings 新增
"settings": {
  // ... 原有字段
  "calendar": { showLunar: true, showSolarTerms: true, showHolidays: true },
  "bookkeeping": { defaultAccountId: "", defaultCurrency: "CNY" }
}
```

关键设计点：

- 复用现有**软删除 + `updatedAt` / `localModifiedAt` + 同步墓碑**机制（`deleted` 标记，不物理删除）。
- `bookkeepingCategories` 与日程 `categories` 完全分离（决策 #1）。
- `memorials` 是独立实体，不走 events 的 startTime / endTime；农历生日用 lunar 库每年换算公历日期。
- 节假日数据依赖 `lunar-javascript` 内置（至 2026）；自定义 / 新年度数据存 `settings.holidayData`（导入后合并覆盖）。

## 四、技术方案

1. **农历 / 节气 / 节假日**：引入 [`lunar-javascript`](https://github.com/6tail/lunar-javascript)（零依赖）。封装 `shared/lunar.js`（UMD，与 `utils.js` 同模式）纯函数：
   `solarToLunar(ts)`、`getSolarTerm(ts)`、`getHoliday(ts)`、`lunarDateToSolar(year, month, day)`、`isWorkday(ts)`、`nextMemorialOccurrence(m, year)`。
   渲染端 `<script>` 引入（`window.LunarUtil`），主进程 `require` 同一份。

2. **生日提醒链路**：`main.js` 现有 `checkReminders` 30s 轮询扩展纪念日检查（`nextMemorialOccurrence` + `remindBeforeDays`），复用 notified / snoozed 与通知 UI；`shared/digest.js` 增加纪念日段落（A7）。

3. **记账模块**：
   - `shared/bookkeeping.js`（纯函数，可测）：`accountBalance(account, transactions)`、`monthlySummary(transactions, from, to)`、`categoryBreakdown(...)`、`budgetStatus(budgets, transactions, month)`、`applyTransfer(...)`。
   - 渲染端新模块 `src/renderer/js/modules/bookkeeping.js` + 侧边栏「记账」入口，四个子页：明细 / 账户 / 报表 / 预算。
   - `store.js` 扩展 accounts / transactions / bookkeepingCategories / budgets / memorials 的 CRUD（复用 touch / commit / 软删除模式）。
   - `saveData` 载荷、`main.js` 的 `data:load` / `data:save`、`preload.js` 同步扩展新数组。

4. **迁移**：`migrate.js` `DATA_VERSION` 3 → 4，`migrateV3toV4` 补齐 5 个新数组 + `settings.calendar` / `settings.bookkeeping` 子对象。

5. **测试**：`test/lunar.test.js`、`test/bookkeeping.test.js`、`test/memorial.test.js`（`node --test`，纯函数优先）。

## 六、风险与后续

- **农历生日换算边界**（闰月、跨年）——lunar 库已处理，需补单元测试。
- **节假日数据时效**——2.3.0 内置至 2026，2027 需升级库或导入数据（A5 已留口）。
- **记账金额精度**——统一整数「分」存储，杜绝浮点误差。
- **同步与移动端二期**（决策 #5）：本期不做；后续需扩展 `shared/sync.js` 的 `ENTITY_TYPES` + server 表结构 + RN 页面。
- **后续（2.4 / 2.5，方案三增量）**：AI 一句话记账、消费关联日程 / 差旅报销、预算 - 复盘闭环。
