## 二、执行方法

### 2.1 测试方法

- **分层全量**：单元/边界/迁移/同步/NLP/农历/记账 202 项（`node --test`）→ 渲染层集成（最小 DOM shim 真实加载 store + 视图模块）→ 端到端（Playwright `_electron` 驱动真实应用，35 断言，遍历 10 视图与全部表单/按键/落盘）→ 打包后冒烟（驱动真实 `.exe`，6 项）。
- **10 轮全量 + 回归 + 系统 + 验收**：全程自动化，发现即修。
- **时间确定性**：依赖时间的排程测试用 `withNow()` 固定时钟，避免 18:00 后误报。

### 2.2 打包方法

- electron-builder NSIS（`oneClick:false`，可改安装目录），`--publish never`。
- 产物 `日程管理 Setup 2.3.0.exe` + `.blockmap` 差分文件。
- 静默重装挂起（NSIS assisted 卸载器需 GUI）时，改用同源打包代码的 `win-unpacked/日程管理.exe` 完成冒烟验证。

### 2.3 文档生成方法

- 内容以 Markdown 撰写 → 脚本转 HTML（A4 样式、中文内嵌字体）→ 本机 Chrome `--headless=new --print-to-pdf` 打印为 PDF。
- 校验 PDF 头 `%PDF-1.4` 与页数，确认无乱码 / 无空白。

### 2.4 GitHub 发布方法

- 提交源码 → 打 `v2.3.0` tag → 推送 → 触发 `.github/workflows/build.yml` 自动构建 mac + win 安装程序并发布 Release（`softprops/action-gh-release`）。
- 安装程序与本地 `发布/`、`dist/` 目录不入库（走 Release 资产 / 本地交付）。
