### 2.2 发现并修复的 Bug

**Bug：跨天的全天日程在「今日规划」时间线中遗漏**

- 现象：当全天日程跨越多天（如「连续假期」，从昨天跨到今天），其起点落在「今日窗口」之外，导致该实例被 `expandOccurrences` 从「今日规划」时间线里漏掉。
- 定位文件：`src/renderer/js/modules/plan.js`
- 修复：对全天事件，把窗口起点**前移一个事件时长**再展开，确保跨天实例不会因「起点在窗外」而被漏掉：

```js
// 修复前
Utils.expandOccurrences(e, { from: dayStart, to: dayEnd }).forEach(...)

// 修复后
const dur = (e.endTime || e.startTime) - e.startTime;
const expandFrom = e.allDay ? dayStart - dur : dayStart;
Utils.expandOccurrences(e, { from: expandFrom, to: dayEnd }).forEach(...)
```

- 验证：新增回归测试「全天跨天日程在今天的时间线中不遗漏」，通过。

### 2.4 测试过程中修复的测试稳定性问题

**问题：依赖时间的排程测试不稳定**

- 现象：「有预估耗时的待办进入时间线」「应用排程按钮」两测试偶发失败，原因是测试运行时 `Date.now()` 已过工作时段（18:00），`autoSchedule` 排不进任何时间块。
- 修复：新增 `withNow(ts, fn)` 辅助函数，把 `Date.now` 固定到 `dayStart + 10 小时`（10:00，处于工作时段）再执行排程断言。

### 4.4 遇到的问题与解决

**问题：Electron 二进制缺失，PDF 首次生成失败**

- 现象：运行 `npx electron README/_build-pdf.js ...` 时报 `Error: Electron failed to install correctly`，`node_modules/electron/dist/` 目录与 `path.txt` 不存在（`fetch failed`，无法在线下载二进制）。
- 排查：检查本机 Electron 缓存 `%LOCALAPPDATA%/electron/Cache/`，发现已缓存 `electron-v43.4.0-win32-x64.zip`。
- 解决：
  ```bash
  unzip -q "<缓存目录>/electron-v43.4.0-win32-x64.zip" -d node_modules/electron/dist
  printf 'electron.exe' > node_modules/electron/path.txt
  ```
  补齐二进制后，三份 PDF 全部正常生成。

> 说明：`tar -xf` 初次解压失败（Git Bash 下 `bsdtar` 解析 Windows 路径报 `Cannot connect to C: resolve failed`），改用 `unzip` 成功。
